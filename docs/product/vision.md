# 产品愿景

**状态：Proposed · 待评审**

## 1. 产品定位

ConnectionAgent Skill Studio 是一个面向 Agent Skill 的设计、编辑、理解、验证和资格验收工作台。

它不是普通 Prompt 编辑器，不是单纯的 YAML IDE，也不是通用 BPMN 流程建模器。它需要同时理解 Skill Package 的业务说明、形式化流程、事实判定、完成契约和测试义务，并把这些资产组织成一个可导航、可编辑、可验证的工作空间。

## 2. 要解决的问题

当前 Skill 资产分散在 Markdown、YAML、Schema、Case 和 Script 文件中。作者需要手动完成多种跨文件工作：

- 理解一个 Skill 的业务目标和适用边界；
- 理解 Procedure 的主业务流程、节点阶段和分支；
- 在多个文件之间追踪 Predicate、Observation、Capability 和输入输出绑定；
- 判断源文件究竟通过了哪一级校验；
- 识别哪些 Case 只是语义验收义务，哪些才是可执行 Fixture；
- 在修改后判断历史验证证据是否仍然适用。

仅有文本编辑器会让作者承担大量跨文件心智负担；只有流程图又会掩盖底层 DSL、类型和状态语义。

## 3. 核心价值

1. **业务流程可理解**：不读完整 YAML，也能先理解 Skill 的业务主干。
2. **形式化定义可控**：图形视图与源文件视图共享同一份源资产。
3. **跨文件关系可见**：从 Procedure 节点追踪绑定、Predicate、Capability 和 Contract。
4. **校验结果可信**：每个状态都说明检查范围、证据来源和适用的源版本。
5. **复杂度可渐进展开**：主流程保持清晰，细节按需展开。
6. **安全演进**：不认识的字段和语法不会被编辑器静默删除或重写。

## 4. 目标用户

- Skill 作者 / 业务设计者：表达业务目标、边界、业务流程和完成条件。
- Skill 工程师：精确编辑 Procedure、Binding、Predicate、Contract 和 Script。
- 验收 / 可靠性工程师：查看 Case 覆盖、验证结果、执行 Trace、失败原因和证据来源。
- Agent / Runtime 集成开发者：理解源资产如何被解析、校验和交给现有执行链路。

## 5. 产品体验原则

- 业务流程优先于文件结构，但文件结构始终可访问。
- 渐进披露：先展示主干，再展开阶段、绑定和证据细节。
- 源文件权威：图形是投影，修改必须写回源文件。
- 语义精确：Predicate、Mutation、Procedure 状态不得混淆。
- 证据驱动：PASS 必须有明确的检查记录。
- 安全默认：预览和静态校验不产生外部副作用。
- 可逆编辑：修改可撤销、可比较、可恢复。
- 诚实呈现：未运行、阻塞和不支持不能显示为成功。

## 6. 成功标准

产品原型至少应证明：

- 作者能打开并理解一个简单 Skill 和一个复杂 Skill；
- 作者能从流程节点导航到源文件、Predicate 和绑定定义；
- 修改源文件后图形投影同步更新；
- 图形修改不会丢失 YAML 注释、顺序或未知字段；
- 当前 Demo 的特殊 CreatedSession 语法不会被错误地按通用 Schema 拒绝；
- 校验结果能区分 PASS、FAIL、BLOCKED、NOT_RUN 和 Stale；
- Case 义务不会被误报为已执行测试；
- 编辑器不会在未确认时触发真实网络操作。

## 7. 产品不变量

- 编辑器不拥有 Agent 决策权。
- 编辑器不拥有 Observation 的事实权威。
- 编辑器不定义新的 Skill Runtime 语义。
- 编辑器不把 LLM 生成内容直接提升为可信 Skill。
- 编辑器不以图形模型替代 YAML / Markdown 源文件。
- 当前阶段只承诺适配 ca-agent-demo 已观察到的能力。
